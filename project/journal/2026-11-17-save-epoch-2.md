# Save epoch 2: the one planned wipe

> Written by: Claude (opus-wr8, WIRE-STABILITY WR8b)

J197 and J210 promised one wipe at the wire v1 cut, then none. The wire itself cut over back in v0.1.x (WR5), so what
was left was the save epoch. The Opus review (meta `docs/plans/wire-stability/WR8-REVIEW.md`) split the wire tag
(shard-format `wire-v1.0.0`, shipped) from this commit, so the MMO's additive wire rows never waited on a wipe.

Two things the bare epoch bump would have got wrong. First, without a floor raise, an old cached page keeps playing its
epoch-1 local progress while the server already holds fresh epoch-2 rows: the player loses progress twice, in two
places. The floor goes to 0.1.36, so J383 forces every older client over exactly once. It clears caches only, never
storage, so the device identity and sign-in survive. Second, the device carry list predated voice, title prefetch and
the telemetry install id, so the cut would have reset voice preferences and made every phone look like a new install.

Nothing is deleted. Epoch-1 rows stay in Postgres and `@1.*` stays on each device, so a restore remains possible if
Jake ever wants one. The epoch can't be lowered (publish refuses), so a bad cut is fixed forward.

**Review fold.** The one-shot review found the readers the prefix scan could not see: proof scripts and the
released-save T1 spec named the IndexedDB database `wildshard-saves@1` rather than the `save.v2@1.` prefix. The scan
now covers database names and `scripts/`, and the stub it fooled asserts the name it opens.
