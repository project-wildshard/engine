# TC22's hatch names the fixing commit

> Written by: Claude (opus-rel97)

Two tags in a row (v0.1.96, v0.1.97) were held by TC22 on a red nightly whose failures a later main commit had already
fixed, and the only way past was `--no-verify`, which also skips the changelog, AGENTS.md, format and pin checks.
`ALLOW_NIGHTLY_FAILURES=<sha>` replaces that: the fix must be on main, come after the nightly's head and name its run,
and every new failure must be one the fix names (a head phase word, a runner job word or the whole key). One failure
it does not name still holds the tag, so a new red can't ride through on an old fix. On nightly 45818175476,
`0421c4c60` names all 165.
