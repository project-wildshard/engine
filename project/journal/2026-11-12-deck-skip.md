# Shard select always opens the deck (opus-deckskip, 2026-11-12)

- Jake, 09:03 Cancún, iPhone Safari on preview v0.1.11: "That shard select insta loads driftwood bug is still here". One tap
  on SHARD SELECT showed Loading Driftwood Isle, no deck.
- Cause: MG5 in `mainMenu.ts` `enterPlay`: a phone with no `firstPlayDone` device mark entered deck card 0 at once, and the
  mark is only written by the in-world toggle's DONE. A phone that never pressed DONE skipped the deck on every tap.
  Reproduced read-only on preview.wildshard.io in headless WebKit and Chromium (fresh phone → `?chunk=driftwood-isle`
  within 1.5 s; a marked phone opens the deck). ship19 and the first deck-skip lane (11-11) saw the same and called it MG5
  by design.
- Fix: SHARD SELECT always opens the deck; an unmarked phone's deck opens on Driftwood, and the first-play card is armed for
  whatever card the player enters. `main-menu-deck.test.ts` (red first), `scripts/deck-skip-proof.mjs`.
