# DL21 / DL23: the boot card's last gaps, and Nine's first-frame program

> Written by: Claude

J198: "warm shaders before control"; DOWNLOAD's DL21 fails a card unchanged for a second, DL23 a loading frame over
250 ms. After DL23's census (`4e46794`, engine job 139) the Simulator sweep (flow + pairs, 24 packs runs, Mac load
10-90) still read 7 runs with the card held 1.0-1.4 s at Props, at the Shaders link wait and at Region world, Sky
frames of 298-357 ms on Pine cold, and one program Nine links in its first frame. Each was profiled to its cause:
Chromium on ANGLE Metal with a CDP profile at 4x CPU, desktop WebKit link probes, and the Simulator's own
ScriptProfiler (its sample timestamps read 0 there, so a scratch run aligned them with depth-coded page marks).

## Nine's Props: the material graph's GLSL emitter

Nine's held Props card ('product read', 'assembly scenes', 'Spawn tiles 9 / 9 · coarse cover') was the material
catalogue compiling its kit graphs (~2,100 nodes, ~90 selects each) in `emitGraphGlsl`: 713 ms of a 1,085 ms still
at 4x CPU on Metal, most of it in `branchShared` and `sameCondition`. Each select rebuilt a reader index of the whole
graph by array spread, rescanned every node for selects on its condition, and walked each candidate's cone again. They
are now memoised per scope: the reader index, the selects by condition, each select's arms' reach, and a root-level
`samples` answer. Output is byte-identical: every graph material of six shards (204) fingerprints the same before and
after. Node, best of two: Nine's architecture 34 -> 13 ms, the six shards' 204 materials 325 -> 195 ms.

## Pine's Sky frame: PMREM's programs linked in the bind's frame

Pine's keyed sky lights the scene from an equirect pass that PMREM filters. Its first refresh runs at the backdrop's
bind, inside one frame, and there the environment pass's, PMREM's equirect and its GGX programs linked synchronously:
the Simulator samples of the 312 ms Sky frame (Pine cold) are 166 of 168 in `getProgramParameter` under
`SkyEnvironment.refresh` (`_textureToCubeUV`, `_applyGGXFilter`). A scene source already had an offscreen first build
on WebKit (`prepareOffscreenBuild`); an equirect source had nothing. Now the backdrop runs that first build on
capturing commands (`warmOffscreenBuild`: no draw reaches the GPU), links what it would draw through `runPrecompile`'s
parallel wait, frees the output and hands the generator to the environment (`SkyEnvironment.prime`), so the bind's
refresh draws with programs already linked and its own materials and ping-pong target. WebKit only, as the scene path;
elsewhere nothing changes.

## Nine's first-frame program: a colourless instanced twin

Nine's one first-frame link is `graph:material:nine-architecture` with `USE_INSTANCING` and no instance colour, drawn by
a parked draw (desktop WebKit link probe; the Simulator's 456-711 ms First frame frames are `fenceSync` behind it). The
census included its mesh, but the scene jobs dedupe by (material, program key) and read the key before the stand-in
gives the live mesh its white instance colours (NF15, `prepareInstances`): the first colourless twin became white and
compiled the coloured program; a second twin kept the colourless key the first had left, was skipped, and drew
colourless at its first parked draw (its own white colours come a frame after a draw). Every included mesh now takes
its white colours before its key is read. Link probe after: First frame 1 -> 0 links on Nine.
The readyFrame step still links Nine's -cut, -ground and -plain instanced colour programs through the async compile
of the spawn ring's fine tiles that attach there; those are not first-frame draws.

## The Shaders link wait: a pass showed its count only at its end

The boot batch's link wait asks each unlinked program's COMPLETION_STATUS, pausing a slice whenever its budget is spent;
on the Simulator each ask waits ~20 ms behind the GPU process's queued links (O14), so a pass over 40 unlinked programs
was a frame apiece, and the card showed the pass's count only at its end: 1.0-1.6 s on '46 / 87 programs linked' while
links landed. Each slice now shows the links landed so far; the wait, its bound and its order are unchanged.

Both precompile fixes carry a test in an existing file that fails without them: a second colourless twin keeps
`instanceColor` null (`precompile-variants`), and a pass whose links land a slice apart shows only '4' instead of
'1', '2', '3', '4' (`precompile-link-count`).
