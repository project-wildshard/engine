# Native loadout owner proof

The SDK native-loadout row mixed real authored policies with direct
ownership flags. Its 1,200-frame oracle also called the same production
controller as its subject. Preserve those public contracts with an
independent slot/clock oracle, and obtain the flags from real inputs.

Two explicit CI-only cases load the pinned Driftwood and Pine products.
Actual pickup selects the rifle. Actual clock selection, skip, free
shots, reloads and reward collection earn the King bow. Full normal HP,
ammunition, damage, deaths and boss checkpoints remain. A grounded pose
fixture isolates shooting and collection; it does not claim a walked
fight, live server capacity or disk durability. No direct HP, damage,
reward or flag write makes ownership pass.

The same live Pine flag book feeds a separate real native host through
its public author binding. Eighty frames precede the pickup, eighty
follow it and the remaining 1,040 follow the actual King payment. All
1,200 compare an independent clock reference, pick priority, ownership,
lock reads, aim default/clamp/sentinel, reused live/armed sets and the
later afterBodies observer. A pending swap uses the actual save adapter;
malformed restore remains atomic. Both original policy/preflight rows
remain covered, including rejecting a Pine policy in the swept kit.
NaN is an author-frame fallback case, not an admitted network command.

Local complete Node run: 2 cases, zero skips, 2.94 s including process
startup; individual cases 2.03 s and 0.27 s. Each unchanged 9.5 s case
bound includes product loading, physics, inputs and cleanup. The file
is outside hooks and Vitest and runs explicitly in CI after the two
ordinary product installs. The old SDK file is retained for its owner.

Four actual source mutants fail the proof: denied ownership (1.28 s),
stale live publication (1.26 s), clamped sentinel (1.28 s), and mutation
before invalid restore validation (2.97 s). Each original source byte
is restored; no runtime source change belongs to this row.
