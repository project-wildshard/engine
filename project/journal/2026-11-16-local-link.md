# Local products beside pinned engine development

> Written by: Codex
> **State:** LL4 in progress, 2026-11-16.

M1 keeps the canonical checkouts on main. LL1 proved SDK links and
restoration. LL4 admits a built unpublished product through the same
format validator as a published pin, before changing installed bytes.
It records local provenance outside the tracked pin book and refuses
conflicting mounts. Full pinned restoration clears that provenance only
after successful installation. CI refuses the explicit local command.

The integration proof changes the local product mount inventory, admits
those unpublished bytes, cooks them with the production encoder, opens
the real cell world with physics, spawns a player and advances a tick.
Normal installation restores the public pin and removes the local mount.
Malformed receipts, links, conflicts and CI use refuse before replacement.

LL5 checks the operator checkout before main-push takes its lock and
before native pre-push creates a clean gate copy. Legacy land and
release preflight use the same guard. Installed slugs and the exact
normal pinned restoration command appear in each refusal. Hosted CI
refuses a planted marker without reading its contents.
