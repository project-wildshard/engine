# 2026-11-17 MMO failure modes (opus-mfm, plan/mfm)

- FM6 mode 44: pickup packs were a bare fetch + hash check, so a truncated pack ended the
  load on "Something broke". They now go through `readContent` with exact length and a
  `verify` (hash) port: a bad file is a broken read (reload retry, then the card's RETRY,
  `packs-5xx pack-broken`). Surprise: after the heal RETRY still got the truncated bytes:
  the HTTP cache kept the 200. Every read after any failure now uses `cache: 'reload'`.
- FM8m mode 41: Redial keeps FM7b1's coded close fact (`progress.ended`); a coded `banned`
  ends the link even before the first frame (it can't be an old server's cut). linkScreens
  shows the removed card: the end time only when sent, else "no end time was given"; Title
  screen only, no Play again, no redial. `failmode-proof --scenario=banned` sends the coded
  close through the proxy twice (with/without untilMs) and counts zero redials. Harness:
  pack-broken presses mode 36's Try again when the job gave up before the heal.
