# MP0.4: real-socket bots, a replica and staging

The bots are `RoomBot`s, the phone's network end the dedicated tests
already use, with `headlessJourney`'s route cursor as the thumb: a ring
of six points around where the bot stands, steered by the feet the
server sends back. `edge` mode moves on from a waypoint a wall holds;
without it two of four bots spent the run pushing at Driftwood's dock.

They are built from the release's own commit (its tree, an offline
install, build-server's `--entry`), because the door refuses another
build or wire. `replica` runs that release's exact bundle on loopback
with production's shape; `staging` joins the staging socket. There is
no production mode, and the bots refuse any socket but loopback and
staging.

The first 32-bot replica run seated 4. The door allows 4 sockets and 10
connects a minute per address, and every bot was 127.0.0.1. Behind
loopback the door reads the proxy's X-Forwarded-For, so replica bots now
each say an address from 198.18.0.0/15, as 32 phones would. Staging
gets no such header: through Funnel the bots are this Mac's one address,
so at most 4 join, which is inside staging's seats anyway. That the door
trusts the first X-Forwarded-For hop from loopback is VPS-HARDENING
VH10's, and is not used here against a live server.

## The review's must-fixes

The target check was asserts in the entry, tested only as text, so
`true ||` in it passed every test. It is now one pure guard
(`mmoBotsGuard.ts`) the tests call with production's URLs, and the
driver copies it into the release tree beside the entry. Staging's free
seats are checked again just before the first hello, since the build
in between takes seconds, and the replica stops on any exit, error or
signal rather than only on the happy path.

The re-review found the stop still racy: clearing `room` before its
process had gone let a second signal skip both the wait and the exit
hook. Now one stop is shared, `room` stays set until exit, the bots
child is told to stop first (and its bots leave their seats on SIGTERM),
and signals exit 130/129/143. A SIGTERM mid-run left no server or bot
process behind.

The two new test files carry their recorded local full and Ring 1 clocks
(push-test-timings record), as every new test file must.
