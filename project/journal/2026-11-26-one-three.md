# The page runs one three.js: the online shell no longer carries an app (opus-nine133, meta QA 11-25 row 137)

- The title page imports the online shell (`b/<build>/standalone/online.js`), its own bundle. On v0.1.92 (prod) and
  b2c9e9f3 (staging) the shell's `config-*.js` held a whole second three.js (626 KB raw); the session's own copy is
  `control-0-0-*.js` (825 KB raw, 219 KB gzip). The title loads the shell's copy, entering the game the session's,
  so every player's page warned `Multiple instances of Three.js being imported` and kept two.
- The link: `ui/voiceSettings.ts` read the talk key from `app/runtime`, which pulled `new App()` (anim, GLTFLoader,
  three) into the shell's graph through `online/voiceUi.ts`. The shell's copy of the app had default bindings only and
  lent them first, so a rebound talk key read as B on the online card.
- Now the game lends its bindings (`lendVoiceTalkKeys`, called in `menuSettings.ts` beside the app). The shell builds
  to 791 KB raw, 269 KB gzip, from 1.92 MB and 575 KB: 1.13 MB raw, 306 KB gzip less on every title.
- Guard: `app-build/oneThree.mjs` walks a build's page scripts (the documents' import maps and the shell entries they
  import by URL, never workers) and the build refuses a second `__THREE__` writer. `test/one-three.test.ts` builds the
  real shell and finds no three in it.
