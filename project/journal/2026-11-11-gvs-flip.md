# Engine installs on pnpm's global virtual store by default

Meta GVS-PLAN G9 (J220, J230), engine first in J230's order. G1 to G8
and G10 are done: the cook grants its exact store slots, the types peer
is declared, the export linker reads through links, the full gates and
Ring 1 passed on the store, and `make prune` waits for this flip.

- `pnpm-workspace.yaml`: `enableGlobalVirtualStore: true`, and
  `confirmModulesPurge: false` so a classic worktree's next non-TTY
  install moves over instead of aborting
  (`ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY`). land.mjs passes the same
  flag on its own (plan/land-purge).
- Hosted CI: pnpm 10.34.9 turns the store off whenever `ci` is true, so
  ring-setup, server-release and size-watch install with
  `--config.ci=false`; setup-node's pnpm cache keeps the store, and
  `scripts/assert-store-layout.mjs` proves the installed layout.
- setup-node's cache key also hashes `pnpm-workspace.yaml`: keyed on
  the lockfile alone, an exact hit from a classic run never saved the
  first store `links/`.
- Review folds: a vendor asset's bundler key now climbs out of the
  checkout into the store's `links/`, so `bundlerSources` keys any
  above-project path with a `node_modules/` by its package path, or a
  recorded `asset-source:node_modules/...` identity would miss.
  `link-node-modules` repairs a missing dependency from the store's slot
  when `.modules.yaml` names it, and `mmo-bots` installs its release tree
  with `--config.ci=false`. `push-dependencies` still returns null on the
  store, so push-proof reuse misses the cache until its own row.
- Not here: `deploy.yml` (Vercel, another lane's file) stays classic until
  that lane adds the flag; the VPS cook worker's install moves with the
  rebuild once its cook.env is back (MMO-SERVER-PLAN MS2.4).

The lockfile is unchanged; this worktree itself moved to the store with
a plain frozen install, and its cook and linker tests pass there.

Branch CI then went red in three export tests on one line:
`@wildshard/wire-released` is a github alias, and on the store its slot
holds the package as `@wildshard/wire`, so the linker's name check
refused it as "outside the repo". A slot now lends an alias only when
the checkout's own package.json declares it (non-registry, or `npm:` of
exactly that package) and the slot is `node_modules/<real name>`.
