# Report-only disk ownership

> Written by: Codex

> **State:** implementation on plan/repo-disk, 2026-11-15.

J358 keeps disk-removal decisions with agents. The scratch sweep,
SessionEnd and worktree reap now report leftovers; the reaper never
removes a worktree or branch. Land alone copies recoverable state before
removing its own just-landed worktree. Copy failure retains the source.

The shared lane reader uses receipts, sessions, active agent hours and
process evidence. Owner metadata carries the lane and plan row. New
worktrees enforce the kit's six-worktree cap and free-space floor.

Real-Git tests cover worktree creation, read-only reap and land cleanup.
The old reap-removal cases were replaced because J358 removes that path.
Opus's four MUST findings are addressed: ignore root ownership, protect
reused lane names with receipt cursors, compare complete worktree state
after stopping writers, and exercise copy failure, generated patches and
shutdown writes through real-Git land tests.
SDK's review also found same-session reuse retained the previous cursor.
The shared maker now refreshes it atomically; SessionEnd omits live dev
parents from its cleanup reminder. The new fixture covers both cases.

DK10a clones the canonical checkout's ignored dist-content on APFS.
The next split preserves identical content inodes and replaces only
changed paths. Its full desired-path marker also resumes stale pruning
after interruption; linked content roots are refused before any prune.
Fixtures cover inode retention, changed/stale output, interrupted splits
and isolated writes to the cloned worktree output.
