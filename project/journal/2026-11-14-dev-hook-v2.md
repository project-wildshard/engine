# Dev hook v2 (SHARD-SOURCE stage 5, opus-ss5)

- AP17: `setLook` takes the whole look section; a data look's `liveLook` sets keys, sun arc, exposure, tone, vignette
  and bloom in place, refusing what was built once (light rows, LUT, fog kind, an exposure the chain lacks). The
  mapping lives in `devScene/liveLook.ts`, not `shardfile/look.ts`: any edit under `client/game/shardfile` moves the
  shardfile validation revision and stales every `out/` receipt (the devserver client build refused to run).
- AP18 (hook v3): `setGround(bytes)` takes the whole 257² ground as one terrain tile's wire bytes. The page swaps its
  terrain heightfield (`swapTerrainCollider`), installs the new field into the bound heightfield, cuts again only the
  drawn tiles whose lattice window changed (`refreshTerrainTile`, the same arrays `installTerrainTile` makes; GPU-only
  normals and colours refill their buffers in place with `refillGpuOnly`) and lifts the player out of the new ground;
  the in-page server gets the heights over the harness port (`__workerClientDevGround`, set in the standalone shell so
  `shardfile/clientWorker.ts` and its validation revision stay put), swaps its own collider and height query and lifts
  its players with `place`. New part boxes lift a player inside them too.
