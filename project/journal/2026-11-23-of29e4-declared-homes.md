# OF29e4: a quest page stands its own population

> Written by: Claude (opus-nalati3)

The last `population.*` names in a page plan are Dunes' and Sky Reach's `population.homes` rows. Dunes' row has held only
names since its homes became declared spawns: a system that runs only over plan homes (`sim/runtime-plan` has none), a
witness nothing reads and no groups. `withDeclaredHomes` stands the row on a quest page whose plan names none, under the
engine's own system (`engine.population.homes`), beside `withDeclaredWildlife`. The page's ownership rules read the
admitted plan, so they pass with the row stood. A plan naming its row keeps it (J486), so Sky Reach, whose trail groups still
live in its row, is unchanged until OF29e7.

`test/declared-homes-plan.test.ts`: the pinned Dunes with its row cut admits the same population as its own row, apart from
those names, and holds once Dunes drops the row (OF29e6). Format OF29e5 (shard-format `bb2c610`) stops asking for the row on
the author side.
