# MP1.2 the first cap: a cheaper Nalati tick (opus-cap)

> Written by: Claude

- Nalati with 32 bots on the box (cpus 9-13): p95 mean 11.7 ms, worst 13.8 ms, over the 10 ms bar. A local `--cpu-prof` of
  the cell worker (32 bots, 45 s) put Rapier's character controller at ~36% of busy time (all inside the wasm call),
  snapshots and sends at ~14%, the seats' held arms ~9% (a weather snapshot and two schema parses a seat a tick), the herd
  law ~4%, GC ~3.5%.
- Every change is exact: same wire bytes, same feet. `NetRoom.view` read each row's class, offset and position again for
  every client, an object and a closure per row per client; one read per frame now serves all of them (`placesOf`, keyed on
  the frame, its tick and the handle serial). The row sample loop drops its closure, the trusted step's finite check builds
  no arrays, and every seat shares one wind schema instead of building one a tick.
- `test/room-frame-bytes.test.ts` hashes every byte a Nalati room sends 12 clients at 3/40/90/160 m and every body's feet over
  360 ticks; the digest was taken with the old code in place and the new code gives the same one.
- Rapier's controller is the bulk and stays as is: autostep, snap, slide and impulses all change where a body ends up.
- `mmo-bots.mjs --server-from <commit>` runs a main commit's server on the box under the release's build name, so a
  speed-up is measured before staging carries it. The ssh links send keepalives: the first 30-minute run's tunnel reset
  about 145 s before the end, which is why every bot read `lost` and steady was 0.
- J206 review (Codex, NO-GO, 2 MUSTs, folded): the bench's remote env line now takes only checked slugs and numbers
  (`--cells`, `--workers`, `--seats`), and `--server-from` builds the bots from the same commit as the server, so their
  wire is the server's exactly (the first box read ran the HEAD server against a3c88b54 bots, which the handshake projected).
  The golden test now hashes every body's feet after every tick.

## Second cut (opus-cap2)

- A local profile of Nalati opened as a cell's room (`room: true` with near colliders, so the seats' held arms run as on the
  box; the old golden test and net-bots harness opened it without, so they never ran the arms): the seats' weather snapshot
  and parse were ~3.3% of busy time, the taming law ~3.6%, the owned riding rows' names ~0.4%.
- Exact cuts: the weather owner's wind is read and parsed once per held step for every seat (only the weather's own step
  moves it); the taming law's state, visual, initial, drove and output names are made once per key, not joined every run;
  the riding owned rows' names likewise. Local 32-player p95 4.65 -> ~4.4 ms.
- `test/room-frame-bytes.test.ts` gains the cell-room case: bots hold a bow draw without sprinting, so arrows fly through
  each seat's wind, and every owner's saved state is hashed each half second. Digest taken on f03e8341 before the change;
  dropping the seats' wind copy fails it.
