# Visible failure outcomes wait for real acknowledgement

FM10b starts with an independent lifecycle and bounded device outbox.
Repaint preserves an episode, replacement ends it, and independent hold
cards keep their own id. Hidden/pagehide/disposal stop visible time;
unknown clock measurements do not become invented zeroes. The typed
analytics contract matches the hosted API receiver.

An immutable outcome keeps its id and originating build across restart.
Only an actual successful records acknowledgement removes it. Storage
refusal is explicit, while the live document retains its pending copy.
Read-before-write preserves another document's additions during delivery.
The oldest pending outcomes beyond 32 are dropped to bound device storage.

The explicit page service now observes connected, rendered roots after
their first frame, and carries real presenter clear causes. Repainting
preserves the original level and episode. Scope ownership transfer avoids
an old loading scope ending the newly adopted foot. Pending outcomes use
a registered device save key, and only an HTTP success acknowledges them.
Existing page telemetry starts the service; isolated presenters stay inert.

Link/release/download/voice/loading presenters are wired. The standalone
Doctor bootstrap and its clock-skew row still need integration. Real native
visibility and actual API delivery/refusal/reload proof remain open; these
checks do not close FM10b or FM10c2. No production events were sent, and no
failure UI style or protected entry/HUD file changed.
