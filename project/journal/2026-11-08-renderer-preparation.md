# Renderer agreement before cook

D5 now has a separate renderer input identity.
A shell build id may name singleplayer rather than engine.
The renderer identity is independent of that document id.
It covers tracked client/shared inputs, build tools and host assets.
Dependency locks and versions of dependencies are included.
Package release version, pin data and recorded programs are outputs.
Generated tables and validation stamps do not feed the identity.
An installed engine uses the publisher's matching revision stamp.

The page exposes that identity beside its document identity.
Version metadata and the actual document must agree during capture.
SDK records it in required preparation version 3.
The GLSL table stays version 2 for its existing client reader.
The format fingerprint binds both product and renderer inputs.
Cook compares the recorded identity before returning any rows.
Hash-valued fence rows now resolve both files and mounts.
Missing or invalid preparation names the regeneration command.

An author needs a way to capture after a renderer change.
The explicit WILDSHARD_PREPARATION_ONLY build is that path.
It ignores recorded lists and uses conservative complete data.
It does not relax body hash, size or schema checks.
Final cook never enables it by default.
The preview version document carries preparationOnly true.
The actual production artifact gate refuses that marker.
The source preview helper also uses pinned products after the split.
No deleted shard generator is invoked in a thin engine tree.

Four metadata boundary cases pass in about 0.22 seconds.
They change real client/asset bytes and exercise document stamping.
The real production gate rejects a capture-only artifact.
The cook proof uses an actual pinned Template tar and emitted rows.
It rejects coherent foreign-renderer metadata before output exists.
It rejects changed inputs and consumes hash-valued mounted fence rows.
These explicit proofs remain outside both hook inventories.

This changes no shader algorithm, Three.js code or page layout.
It introduces no save epoch or network wire revision.
Normal publication still requires the full push gate.
Live prepared-head publication requires the author credential.
No credential, VPS setting, bucket or deployment is changed here.
