# Signed cook addresses for rooms

PV24 keeps a placed cell's shard version alongside its upload hash, including
when a catalogue cell switches uploads on a running room worker. A versioned
room uses the signed release's cook address and verifies the requested upload.
An activation with no placement row looks up the exact hash's raw version via
the shardfile catalogue. Existing releases keep their current room path until
the operator enables `ROOMS_VERSIONED_COOK`. A page with a baked zone table
also includes the cooked origin in Clear downloads.

The local room opened Brasscap Mesa from the versioned store with Rapier and
verified its 762,500-byte server part. Both real shardfile canaries matched all
126 common objects against the original tar entries. The focused path,
publishing and Clear downloads suite passed nine tests.

The shared-object sweep tests protect indexes carried by preview after staging
moves, keep production references for seven days and staging references for
one, and fail closed when a kept index is missing. The cook serializes its
daily collection with publication and records the retained shard prefixes for
the API's sweep. The cook hash changed and the same-version golden matched.
