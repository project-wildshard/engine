# Profile and titles (MMO-PLAN MP3.2)

- One `profile` jsonb on `player` (`0005-profile.sql`): titles (M4's Title under the Name, O9's Founding Author), cosmetics and
  achievements, the platform's own things (M6). No global coin (G25): a check constraint lets no other key in, so a coin can't be
  stored even with the guard off. Catalogue gear joins with MP3.4's catalogue.
- Only a ledger grant changes it, and Postgres enforces that, not the app: a profile receipt (`title`, `cosmetic`, `achievement`)
  is filed under the reserved shard `@platform`, and its insert trigger adds the name once. A replayed fact lands no receipt, so it
  adds nothing. A trigger on `player` refuses any other profile write, an insert with a profile, and any update outside that
  receipt trigger. A check keeps profile kinds to `@platform` and `@platform` to profile kinds, so a shard can't mint a title.
- `saves/profile.ts`: `grantProfile` locks the player row, takes the next `@platform` serial and files the receipt;
  `readProfile` reads it back. Nothing calls them in the room yet: grants come from the platform (O9's upload), not a shard's loot.
- No wire change: the client doesn't read titles yet. Showing the Title under the Name is the next UI row's.
- Red first: `test/dedicated-profile.test.ts` with the column but no guard went red on the direct update; green with the triggers.
