# The region cinematic install only where a cell can carry it (opus-cine110, meta QA 11-25 row 110)

- Row 105 named five of the one-cell world's extra programs as the region cinematic install (SF63, G321 part 5): the
  volumetric march, and god rays with their Kawase blur and two copy passes, placed in the shell's colour pass at zero
  opacity so a carried cinematic region never recompiles at the crossing. Brasscap and the open plots run the data look's
  clean chain with phone god rays off, so in their one-cell worlds nothing could ever carry them.
- The frame now asks the catalogue at install what each cell of the world can carry on this tier (`catalogueCarriage`):
  a manifest with no look binding, or one whose binding says it runs the clean chain (`lookChain`, set where a shardfile's
  own data look is its look: no declared post, no painted world), never carries the shafts, fringe or grain, and carries
  god rays only where its tier knob leaves them on. Any look binding the catalogue cannot read is "not known", and then
  everything is placed at install exactly as before. So every world with Pine, Nalati, Nine, Driftwood and the rest is
  untouched; only worlds whose every cell is a known clean, rays-off look skip the install.
- The guarantee stays: a live chain that carries them after all (a catalogue that guessed wrong) gets them as its region
  loads, in `contribute`, with one prepared recompile and the march warmed; a region always contributes before it can
  carry the frame, so the crossing itself still only moves opacities.
- The first try read only "no look binding" and cut nothing on Brasscap: its admitted shardfile's manifest (clientSource)
  always binds a render (the data look), so the catalogue entry has to say the chain itself. Hence `lookChain`.
