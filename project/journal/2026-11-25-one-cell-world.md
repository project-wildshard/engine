# A page that carries one cell boots it (opus-chunk2, CHUNK-PARAM-REMOVAL CP10, J522)

- Jake's J522: `?chunk=` goes, and builder dev becomes a one-cell world on the players' grid path. This is the engine half:
  a page whose `ws-catalogue` holds exactly one cell (`oneCellWorld`) boots that world at its cell on a bare `/` with no tap.
  The entry admits a document-only grid intent (`enterOneCellWorld`), so `bootPageMode` makes it a grid page; the channel
  catalogue has 22 cells, so no player page changes.
- `bootZone()` in entry.ts is the zone the boot enters: the address's until CP22 deletes it, else the one cell's. CP8 can
  take it over as its boot-zone variable.
- A one-cell world reads its own zone's spawn set (`client`), never the grid set, which lists every neighbour's
  discovery; its catalogue read is that one row. An inline author shard that no title row names keeps today's reads.
- index.html's first body script sees the one cell (the head script runs before the catalogue is parsed) and paints the
  zone's loading card instead of the title.
- Proof on a working-tree preview with Pine's one-cell catalogue injected: Pine boots as cell (0, 0) on `/`, no URL names a
  zone, no other zone's level file is read (the in-game menu still shows 9 zone cards' art), and walking out from four
  sides stops at +-1977 m, the 7 x 7's outer road shoulder, as on the whole grid.
- CP11 (opus-chunk2, later): against this engine, `wildshard dev` stopped at boot. The author's inline shard took the grid
  path, then its home was claimed twice (an unplaced product is `external-<hash>`, the cell is its slug), and past that the
  grid admits a cell only by a descriptor whose build owns its residency verdict (folderCost.ts), which an uncooked
  candidate never has: the verdict is build-owned, never a network sidecar. So a page with its own `ws-shardfile` keeps its
  one-shard boot on `/` (no `chunk` either way); the grid path for builder dev is CHUNK-PARAM-REMOVAL CP25.
