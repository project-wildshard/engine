# land judges only blocking CI jobs

Coordinator, 2026-11-10: opus-gridonline's `land` stopped on runs
42925077011/42925077103 and the stop line listed `quarantine (1)`, `(2)`
first. Those jobs are continue-on-error (J193, J200) and never fail a run
alone; the real reds there were `tests (4)`, `(8)`, `(14)`, my worktree
guard on Linux (fixed by c3de0f7). Still, `land` now splits a red run's
failed jobs: quarantine jobs are named as non-blocking, a run red only from
them counts as green, and a run whose failed jobs can't be listed stays red.
Also: the commit-entry worktree test checks `git`'s exit status (J206
SHOULD on 983d09e).

J206 Codex review (three MUSTs): don't override the run conclusion with a job
list at all. Pages, re-runs and cancelled runs can hide a blocking failure,
and main's reuse requires real run success anyway. Quarantine jobs can't make
a run red alone (continue-on-error), so the conclusion stays authoritative and
`land` only names quarantine reds as non-blocking in its stop line.

## Stamp-only rebase conflicts (coordinator, 2026-11-10)

`land` stopped on a rebase conflict in `scripts/renderer-revision.json` almost
every time main moved (opus-gridonline twice, opus-k10). Now a conflict only in
the two generated stamps takes main's side and continues (an emptied stamp-only
commit is dropped); after the rebase, `gen.mjs --inputs-only` regenerates the
stamps for the finished tree and they are amended into the plan's tip (hooks
on). Not mid-rebase: `rendererRevision` hashes HEAD's file list, which before
the replayed commit exists lacks its new files. `classifyRebase` no longer
counts a stamp both sides changed as a shared path, so DS1's stamp check judges
the regenerated bytes and a disjoint plan stays `carried` (no hosted rerun).
The real-Git test uses engine's own `rendererRevision` and a plan that adds an
input file; it fails on the old `land` with the conflict stop.

J206 Codex review (two MUSTs, fixed): only a plain both-modified conflict on a
stamp is resolved (a modify/delete still stops, else main's stamp would undo
the plan's deletion), and only the stamps are amended: other files gen.mjs
rewrites from local products go back to their committed bytes.

## Own-tip check (coordinator, 2026-11-10)

After a stamp-conflict stop, agents rebased and pushed `plan/<slug>` by hand;
`land` then refused origin's tip as "not this worktree's last push" because
it only remembered its own last push (opus-fasttests, opus-ld6b). `land` now
appends every branch push it makes and also counts the local plan branch's
reflog as its own; an origin tip that is one of those, or an ancestor of one,
is this worktree's. A commit the worktree never had still stops it (the
existing foreign-push test). Both new cases fail on the old check.

J206 Codex review (two MUSTs): a reflog proves the branch pointed at a commit,
not who pushed it, so a fetched or merged foreign tip would have passed. The
reflog no longer counts. Instead the pre-push hook records every plan/* push
from the worktree, hand pushes included (`.githooks/record-plan-push.mjs`), and
ownership is "one of those pushes or an ancestor of one". New test: a foreign
tip the branch was reset to or merged, then left, still stops.
