# LF2-3: a post graph's world ray (opus-lf23)

> Written by: Claude (opus-lf23), 2026-11-12 ~02:20 Cancún.

- Brasscap Mesa's sky (meta TEMPLATE-E2E-PLAN LF2-3) paints salmon
  cloud streaks and a sun glow in its own `look.post` graph. Template
  1's graph (MH-1b) keys its clouds to `screenUV`, so they swim when the
  camera turns. The post vocabulary had no world direction: the
  fullscreen pass draws with its own camera, so `cameraPosition` there
  is not the scene's.
- New op `viewRay` (format, shardfile `4868120`): the world-space unit
  direction from the scene camera through the pixel. The lowering is
  `normalize(F + (u·2−1)·R + (v·2−1)·U)`, three host vec3 uniforms
  (`wsViewForward`, `wsViewRight`, `wsViewUp`) that `ClassicPostPass`
  sets from the scene camera's world matrix each frame, right and up
  pre-scaled by tan(fov/2) (× aspect for right), divided by zoom.
  No mat4 host uniform type needed.
- Proof: `graph-scene-post.test.ts` (basis for a camera turned a
  quarter); a 12-frame orbit at the porch on a Brasscap preview: the
  sun glow and the streaks stay put against the mesas.
- `@wildshard/format` moves to `4868120` for the op.
- Codex review, two MUSTs, fixed: the feed assumed a symmetric
  frustum (a view offset, as the explorers set, misaimed every ray), so
  it now unprojects the centre and the right and top edges through the
  camera's own inverse projection, at unit depth; and the scaled post
  executor (`game/looks/scaledPost.ts`) compiled `viewRay` graphs
  without feeding them, so the feed moved to `render/graph/viewRay.ts`
  and both executors call it each frame. Test: a right-half crop.
