# 2026-11-11: the grid gate on the rooms address (opus-gridgate)

GO4's gate read `<socket>/health` to decide whether a grid page joins the world. D7 made `/health` private on rooms (Caddy passes
only the upgrade), so on rooms the gate always said no and the grid stayed one-shard; loopback hid it. The door now sends a
`world` word (`{cells}`) first on every socket, before hello, and the gate reads it on a socket of its own and closes it. No box
or Caddy change. `scripts/grid-gate-proof.mjs` proves it behind a front door that 404s `/health`.

Found on the way, not fixed here: a Developer deck's template card aims at the hidden template placement, which `WORLD_CELLS=grid`
doesn't open, so the door seats the player in Driftwood. That's GO7's cell pick.

## The template card's seat (opus-tplseat)

That guess was wrong twice over. The proof's `/template/` matched **Blender Template** (off the grid, so the door's first cell,
Driftwood), and a tap on an off-centre card never selects it (the track captures the pointer), so PLAY entered card 0. The real
**Template shard** card does enter the grid at `template-2`, and the door opens it, but the page dies before the server. The
page admits its arrival shard as a one-shard page (`installManifestShardfile`) before the grid admits the same cell: that
installed a manifest with no descriptor ("_template is not a shardfile shard"), and it claimed the home at the page's cost, so
the grid's handoff refused ("Home residency differs from the admitted whole-runtime cost"). On a grid page that admission now
keeps the descriptor and, for a data home, leaves the claim to session.ts at the cell's regional charge (T7); a declared page
keeps its own claim (Codex). **Not done:** the page now stalls at loading step `home` (Home region) for 61 s with no error,
likely the grid's home admission waiting on a budget the page's own admission of the same product still holds. Driftwood is
unchanged. The proof picks cards by name through the dots and runs a Template leg (seated in `template-2`, walks) and a
Driftwood leg; the Template leg fails until `home` passes.

## The home stall (opus-tplseat2)

Not a budget. Instrumented, the home's whole admission passed (metadata, the regional handoff, the product) and the page
waited in `prepareDataTiles`, on the first spawn tile its entry pinned on the page's ring streamer. The streamer publishes
only on `step`, and only the page loop's late frame steps it, which starts after loading step `home`. A runtime home
(Driftwood) never takes this path; a data home entered from the road in play has frames running. Only an initial data home,
new with GO7's Shard select → Template card, waited forever. `grid/loadingRings.ts` now steps the rings every 16 ms while no
late frame has run, until the entry settles; once the loop runs it owns them alone. Red first in
`src/client/game/grid/loadingRings.test.ts`. `grid-gate-proof.mjs` passes both legs: the Template card seats you in
`template-2` and you walk 8.5 m; Driftwood unchanged.
