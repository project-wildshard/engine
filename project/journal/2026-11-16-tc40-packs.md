# Prove durable pack publication and reads

TC40 names five real boundaries: current CDN reads, cook metadata through
workerd, stored bytes rather than has(), interruption at each publication
stage, and channel builds surviving GC. The old status predates the CDN.

The explicit Ring 2 report uses a pinned real Template cook and its actual
publisher. Publisher processes die by SIGKILL after durable writes, then
fresh processes restart against those stores. Missing and hash-invalid
parts refuse verification and heal. Recorded cook headers accompany the
actual bytes into the frozen legacy Worker in workerd/R2. Current CDN
GET/range/out-of-range reads are independent and read-only.

GC runs the actual CLI against a private old store while reading all live
channel graphs; current and carried builds survive, obsolete bytes leave.
No R2 write, deployment, release or Mac mini cook is part of this proof.
Repeated real cooks exceed ten seconds, so this stays report-only Ring 2,
outside hooks and ordinary discovery. Qualification is evidence, never the
workflow's continue-on-error wrapper. No TC40 credit before all criteria
pass and the coordinator approves the normal land.
