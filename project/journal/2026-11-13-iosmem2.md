# 2026-11-13 iosmem2: Driftwood's textures and the live parser's numbers

> Written by: Claude (lane opus-iosmem2)

Second pass at WILDSHARD-GAME-8G (Jake's iPhone killed staging's page while Playing on Driftwood).

Driftwood did ship a KTX2 table; the page just never used it. A grid resident resolved Auto's texture form before its
shard's table was registered, so `texModeWhy` read "no KTX2 set for this tier" and kept images for the resident's life.
Pine and Far Reach never hit it because their tiers pin `textures: 'ktx2'`. The admission now registers the table first,
and Driftwood loads KTX2 from its first entry (`textures().mode` is `ktx2`). Its own images are few (horizons, the
giant, lightmaps), so the GPU ledger barely moves: most of the ~76 MB of textures are the page's own (grid signs, render
targets, the terrain AO, one screen-sized texture).

The live parser's worker sent the parsed tree as JSON token pages, every number as a string inside a JSON array, so the
page thread made a token array and two strings a number. The transfer is now binary tokens: a number is one tag and a
float64, a string is UTF-8 in 4,096-unit parts (UTF-16 units when it is not well formed). `parsed-pages-heap.test.ts`
measured 399 bytes allocated and 26.8 wire bytes a number before, 33 and 9 after.

The memory proof as an iPhone (local build, Chromium, Playing +10 s): renderer 1,818 MB on images, 1,751 to 1,782 MB
with KTX2, 1,632 to 1,682 MB with KTX2 and binary tokens; the JS heap 665, then 599 to 644, then 425 to 515 MB.
