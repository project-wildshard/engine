# Packs move to packs.wildshard.io (PACKS-CDN PC3)

wildshard.io is on Cloudflare now, so the R2 bucket serves itself on its own custom domain with the CDN in front, and
the wildshard-packs Worker on workers.dev can go (meta `docs/plans/PACKS-CDN-PLAN.md`; PC2's proof passed in WebKit
and Chromium). Every code default that named the Worker now names `https://packs.wildshard.io`.

The one catch from the proof: the free plan's cache key ignores Accept-Encoding, so any client that fills a cold
edge without `br` parks a decoded copy that browsers then get re-compressed. Node 24's fetch sends
`br, gzip, deflate` over HTTPS (the proof's `gzip, deflate` is its plain-HTTP default; Codex's review caught it), so
today's box is fine, but the room's pack reader now asks for `br` only rather than leaning on Node's default. undici
still decodes it, and `undone` still covers a stored `.br` sent raw.

Not here: the GitHub variable `WILDSHARD_PACKS_ORIGIN`, the box env and the channel pages' `WILDSHARD_RELEASE_URL`.
The v0.1.10 release lane sets those, so live v0.1.9 keeps reading the Worker until then.
