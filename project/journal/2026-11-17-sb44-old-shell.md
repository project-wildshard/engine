# SB44: an old shell pulled out of play for stale code (opus-sb44)

- Cause (staging v0.1.38, v0.1.36 WebKit profile, select cold 4 of 5): the online shell dialed its kept release file at once, the
  world reached play, and the fresh read (engine build 1dce990f, not 6f53e748) ran `stale()`: `reloadRefusedBuild(true)` waited ~2 s
  for the new worker, then reloaded. The world page's address was bare `/` (GO4), so the reload landed on the title with the drop
  modal, though `titleArrival` (session, tab) still named driftwood-isle.
- index.html: a bare `/` whose young unload is the engine's update reload (stale deployment code / stale build / new build panel, not
  `reload`) and whose tab handed over a fresh arrival gets `?chunk=` back, so the page goes back into the world. Fixes old shells too:
  the receiving document is always the newer build.
- release.ts/shell.ts: a kept copy waits FRESH_WAIT_MS (2 s) for the fresh read when online, so the build is known before the world is
  entered (a reloading page never dials); a later read naming another build after the world seated the page waits for the next visit.
- journey-proof: `stickProblem` reports a page that navigates during the move check instead of crashing the run.
