# OF29e8 engine half: the page population is the engine's own row

> Written by: Claude (lane opus-prune1)

The engine stood a quest page's population by synthesizing the format's `population.homes` row, so the format could never
retire the kind. Admission now makes the engine's own row, `engine.page-homes` (`PageHomesRow`: system, held, holds,
groups), held beside the format rows as the plan's `pageHomes` and run at play rank 60 by the `quest.page` entry's `pageHomes` installer (so the host ruler roots it in that kind): synthesized under `HOMES_SYSTEM` for any quest page, or converted from an older pin's format row (Far Reach r4,
Dunes r5) with its own facts. The format's ownership rules and module checks still read the format rows; format rows stay
free of it, so `client.ts` and `clientWater.ts` (renderer revision inputs) are untouched and the revision holds. Left for the format retire (after OF29e6/OF29e7 pins):
the conversion, `clientPopulationBodies`' raw group read and the headless-population test's format parse.
