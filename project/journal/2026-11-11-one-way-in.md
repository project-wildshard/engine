# One way in (MMO-PLAN GO7), opus-go7

- On a build with a world whose server hosts the grid (GO4's `/health`
  gate), a `?chunk=<grid shard>` page turns into a grid page at that
  shard's cell before anything loads: Shard select, a seat elsewhere and
  a stale-build reload all land in the online grid. One load, no bounce.
- The page asks the door for that cell: the socket address carries
  `?chunk=<instance>` (an allowed name; ZS5 calls it "`?chunk=` turns
  into a goto"). The door seats it there when it opens that cell, else
  the player's last place as before. Without this, walls (DG1) would
  keep a player in their first cell forever. An older door ignores the
  query. PLAY still takes the seat the world keeps (GO5).
- Solo builds (preview, sharddev), a world that hosts only Driftwood
  (production today), EXPLORE WORLD and shards the grid doesn't place
  (blender-template, pastel-plain, ink-cel-valley) keep the one-shard page.
- Infinite Wildshard shows without Developer once the world says it
  hosts the grid (DG4); production keeps it behind Developer until then.
- The 5x5 catalogue already has 25 cells. The server opens 24 because
  the grid spells template-2's shard `_template` and the pins and release
  say `template`. That spelling belongs to the release lane: a half fix
  would point a worker at a pack folder that may not exist.
- Codex review, four MUSTs folded: a seat held in another cell lets go
  on a goto (and a late `left` from that cell no longer unseats the new
  seat); the page's own goto is held in the document, so a boot slower
  than 60 s can't age it out; one 3 s deadline covers the online
  module's import too; a recovery reload asks for the cell it stood in.
  The grid page reuses the goto's hosting answer instead of a second
  read that could disagree.
