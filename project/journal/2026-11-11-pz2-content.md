# 2026-11-11 PAGE-SIZE PZ2: content to R2

- `scripts/page-release/content.mjs <dist>` publishes S1 to S7 and E1
  (D1) to `wildshard-packs` as one content set,
  `content/<set>/<page path>`. `<set>` hashes every path, hash and
  size, so unchanged content names the same set and uploads nothing.
  Chosen over per-shard `shards/<sha>/` keys because PZ3's
  `contentBase` mirrors page paths from one base (coordinator's option
  a, content-named instead of per-build). PZ4 must let `contentBase`
  carry the `/content/<set>/` path: today `readContentBase` and
  `stampContentBase` accept an origin only.
- HEAD skip on packs.wildshard.io, `wrangler r2 bulk put` per header
  set, then a cache-busted CORS read-back of every key. The bulk put
  stops at its first failed object (a 502 on the first real run), so
  publish re-HEADs and retries only what is still missing.
- `page-release.mjs --content` runs it in the upload phase, before the
  packs and the page. Off by default: nothing stamps the base yet.
- Follow-up: a new set re-uploads files an older set holds; cross-set
  dedupe goes with PZ10's content cache.
