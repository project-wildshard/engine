# Page size (meta PAGE-SIZE-PLAN, J276)

- PZ1 (opus-pz1): `scripts/page-size.mjs <dist>` prints a built page's files and bytes by kind (code, shell, runtime,
  engine art, shard content S1 to S7, maps) and the carried builds' share from `deploy-chunks.json`. Report only; PZ4
  makes it a gate. On v0.1.9's production output (`04e1e714`) it prints 2,369.7 MB in 11,303 files, 82% shard
  content, 99.4 MB and 1,377 files carried: the plan's table. Two calls differ from the plan's hand count: the runtime
  (rapier, basis, 3.9 MB) is its own kind, and `assets/music/nalati/` counts as Nalati's (16 files, 6.3 MB).
- `build-vercel-output.mjs` now keeps maps out of `.vercel/output/static`: the hand release path never stripped them,
  so v0.1.9 shipped 122 maps (37.9 MB) that only a 403 header hid. A release build (its release file names production
  or staging, or `WS_SENTRY_ENVIRONMENT`) first uploads them with `sentry-maps.mjs`; a failed upload only warns, since
  `dist` keeps the private copy for the artifact.
- Review (claude -p): page-release's Vercel host runs build-vercel-output without WILDSHARD_RELEASE_URL, so the channel
  now comes from the built page's own `__WS_WORLD__` stamp; a bad `WS_SENTRY_ENVIRONMENT` stops before the build. The
  classifier also counts per-shard `assets/sfx/<shard>/`, `gpu/baked/<shard>/`, `lut/<shard>.bin` and
  `horizon/<shard>-*.webp` as shard content (S7). v0.1.10's output (`98fdd797`): 2,357.6 MB, 11,076 files, 124 maps.
