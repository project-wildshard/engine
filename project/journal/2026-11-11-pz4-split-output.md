# PAGE-SIZE PZ4: the build output splits

- opus-pz4, 22:30 Cancún. `pnpm build:game` now ends with `scripts/app-build/splitOutput.mjs dist`, which moves shard content (S1 to S7) and engine art (E1, D1 yes) to `dist-content/` at the same page paths, and `scripts/page-size.mjs dist --gate`, which refuses a page with any content left or above 1,000 files or 100 MB (maps never count).
- Proof: a local release build (WS_RELEASE=1, production carry of 4 builds) leaves 670 files and 68.3 MB in `dist/` without maps; 10,301 files (2,252 MB) went to `dist-content/`. `shard-size-gate.mjs` reads the packs book from `dist-content/`, and its per-shard phone `wireBytes` JSON is identical to a pre-split build.
- No channel stamps a `contentBase` yet, so page-release joins (`splitOutput.mjs dist --join`) before packaging, and the nightly, hover-contract and engine-boundaries jobs join after `build:game`. CI's own build (`build-app.mjs`) never splits, so the prebuilt artifact and boot-dist are unchanged.
- Seams for PZ5 / PZ8: `content-base-proof.mjs` on the split output boots Driftwood, but the page origin 404s on `/assets/boot-tables-*.json` and `/assets/title/*.jpg` (PZ3 left those reads on the page), so they must read through `contentURL` before a channel stamps a base. And `readContentBase` / `stampContentBase` still take an origin only, not PZ2's `https://packs.wildshard.io/content/<set>/`.
- Review (one `codex exec`): two MUST findings fixed. The shard-size gate reads a book in `dist/` before `dist-content/` (a same-id rebuild never measures an older split), and `splitOutput` marks the page with `.splitting` while it moves, so a retry after an interruption finishes instead of deleting what already moved. Overlapping roots are refused.
