# Rebase private queue jobs without losing source

Nine receipts had a generic pull failure. Actual logs show generated
revision conflicts in immutable job snapshots, not rebases of a dirty
shared checkout. Q69 published while canonical dirt remained. Canonical
held duplicate hook patches are now reconciled; every peer source was
retained and the old Doctor conflict was resolved by its owner.

The queue rebases only its checked private root onto the fetched origin
SHA. A remote advance before the gate gets exactly one fresh fetch and
rebase. Real source conflicts name every unresolved path and remain red.
Only renderer-revision.json and validation-revision.json may be resolved
by the two official stamp scripts, with declared frozen dependencies.
No source hunk is selected automatically and no hook is bypassed.

After all commits are rebased, official stamps are recomputed over the
complete inventory; any final metadata change commits by exact path
through the ordinary commit entry. Every actual publication still uses
its complete normal hook and actual Git push.

Real tiny Git histories reproduce the old failures: generated-only
conflict fails generically, and a real lane.txt conflict hides its path.
Both are green with this fix (3.45s and1.81s), dirty source bytes and its
HEAD remain literal. A real remote advance between helper fetch/rebase
passes4.92s with one gate attempt and retains the raced upstream file.
The original queue environment/FIFO/partial-source proofs remain gates
of this manual verification, never added to pre-commit or pre-push.
