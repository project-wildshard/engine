# VPS build-out on the rebuilt box (opus-vps)

- The box was rebuilt (Hetzner Rebuild, ~13:30 Cancún) and brought back with v0.1.8's `rebuild.sh` and `setup.sh`:
  production serial 6 and staging serial 71 on the Funnel again, fresh saves.
- VH11/VH12: one OS user and database role per channel (`wildshard-<channel>` / `wildshard_<channel>`), peer-mapped,
  each owning one database with CONNECT revoked from PUBLIC. A box from before keeps working: the shared role's objects
  are reassigned and the role dropped, and channel folders change hands once. Proved live: staging's user cannot open
  `saves_production` (pg_hba and the peer map both refuse).
- VH13: `dump.sh` encrypts to `AGE_RECIPIENT`; `restore-check.sh` takes the off-box key as its second argument, since
  sudo drops the environment. Proved live: R2 object starts `age-encryption.org/v1`, restore 397 ms.
- MS3.1: `harden.sh` now applies VH3 to VH15 through `harden-apply.sh` (and `harden-caddy.sh` for VH9 as J264 changed it:
  Caddy behind Cloudflare, Origin CA certificate, Authenticated Origin Pulls). Surprises: ufw's own sysctl file turns
  `log_martians` off on every start; tailscaled holds 443 on the tailnet address while the Funnel lives, so Caddy binds
  the public addresses only; a root `caddy validate` leaves a root-owned access log that stops Caddy; Caddy's `header`
  matcher with several values never matched an Origin, so the allowlist is one `header_regexp`. The dead-man fired for
  real once (fail2ban banned this Mac's tailnet address after root-login polls) and put Tailscale SSH back as designed.
- Second commit: the harden apply half itself (`harden-apply.sh`, `harden-caddy.sh`), its --check changes, tests and docs.
- Codex J206 review (NO-GO, 7 MUSTs) folded: the restore runs as a no-superuser `wildshard_restore` role, plaintext stays 0600, symlinked channel folders are refused, a server left on the old user restarts as its own, every ufw deletion is under the dead-man, `--open-443` removes any non-Cloudflare 443 rule, nftables and Caddy reload only on change (certificate included), `/up` is a bare 503 on failure. Not yet re-reviewed or proved on the box.
- J206 re-review (opus-vpsland, NO-GO again: MUSTs 1, 4, 6, 7 open, plus 2 new) folded: owned folders are made through openat with O_NOFOLLOW at every step (no symlink race), the VH11 hand-over stops servers, pull timers and dump first and refuses if any stays up, ufw drift is judged by port and source never by comment (open, close and apply alike), nftables reloads in one transaction with a live-chain stamp, Caddy validates with its certificate before any restart, and the VH11 check expects `wildshard_restore`.
