# Two Template pages share the real memory MMO

A worker fixture reuses the existing client build, starts the real server
with memory saves and a one-run signed loopback release, and places the
release stamp before the app starts. This is the same stamp contract as
the HTML build step, so no second client build is needed.

Two independent contexts choose Template through Shard select and enter
names through its real prompt. Each sees the other's named body and both
read a chat line sent through the composer. The local Chromium proof
passes in 29.1 s with no console or page errors, and all rig processes
exit. Hosted qualification remains T1E-6c.

The shared entry helper accepts a name instead of racing its automatic
Skip. Rig close now waits for page and world processes, clears its kill
timeout, closes the release listener and ends its log. Preview telemetry,
keys, server build and browser profiles stay in the lane's scratch.
