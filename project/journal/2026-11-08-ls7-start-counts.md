# LS7: real Start code bytes

Written by: Codex. 2026-11-08. Parent a6c9661, fresh ls7-engine clone.

The original strict Dunes phone boot was red: 19.4 seconds to ready and
5.0 seconds without one percent across shaders and first frame. Start
reported only finished resource transfer bytes, with no import body total.

The inline Start reader now uses the compiler-owned common module bank
already in the document. Each completed resource contributes only its
observed decoded body bytes, capped by the emitted file size; duplicate
resource rows cannot credit the same URL twice. A separate real byte
share joins the seven existing completed boundaries. No download,
import, cache policy, duration estimate, CSS or layout changes.

The collector also offers an optional, loader-owned subscription to real
updates. Disposal and collector finish remove subscribers. This lets the
following server change observe a worker which starts and finishes
between the existing 100 ms clock ticks.

Dunes on Chromium at 4x CPU and 12.8 Mbit/s reads all 28 common code
files, 5,114,788 decoded bytes in this build. WebKit reads 27 files in
Start; remaining startup code lands after adoption. The byte share never
claims that missing file. Both keep zero backwards and zero untraced bar
changes. The strict renderer stall remains; LS7 is not complete.
